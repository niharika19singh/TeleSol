# HashKey Settlement Protocol (HSP) v2.3.0 Gateway Integration Guide
## Official Merchant API & AP2 Cart Mandate Specification

This document details the architecture, API contracts, HMAC request authentication, Cart Mandate payload structure, webhook verification, and settlement mechanisms implemented in **TeleSol PayPilot 2.0** for the **HashKey Settlement Protocol (HSP)** / **HashKey Merchant API v2.3.0** (`https://hashkey-merchant.github.io/#/`).

---

## 1. Overview & Protocol Contract

The **HashKey Settlement Protocol (HSP)** provides enterprise-grade, non-custodial crypto payment gateway infrastructure for merchants, payment aggregators, and autonomous software agents.

In TeleSol PayPilot 2.0, autonomous agents execute payments for services discovered via TeleSol Sentinel (e.g. emergency 5G slices, edge compute, IoT sensor telemetry) through HSP using the official **HashKey Merchant API v2.3.0**.

### 1.1. Gateway Role Separation
```
┌──────────────────┐       ┌───────────────────────┐       ┌────────────────────────┐
│ Autonomous Agent │ ────► │  TeleSol PayPilot     │ ────► │ HashKey Merchant (HSP) │
│ (Buyer/Request)  │       │  Backend Service      │       │ Gateway API v2.3.0     │
└──────────────────┘       └───────────────────────┘       └────────────────────────┘
                                     │                                  │
                                     ▼                                  ▼
                           ┌──────────────────┐               ┌────────────────────┐
                           │ Web3 User Wallet │               │ HSK Chain          │
                           │ (Mandate Signer) │               │ (Settlement Layer) │
                           └──────────────────┘               └────────────────────┘
```

- **Client/Agent**: Formulates structured Service Agreements and requests.
- **PayPilot Pre-Execution Simulator**: Deterministically validates 11 safety rules and reservations.
- **Web3 Wallet**: Payer signs the Cart Mandate via EIP-712 or personal sign.
- **PayPilot HSP Service**: Generates RFC 8785 Canonical JSON, calculates SHA-256 body hash, computes HMAC-SHA256 request headers, and submits order.
- **HSP Gateway**: Orchestrates on-chain settlement on HSK Chain and broadcasts webhook notifications.
- **HSK Chain Adapter**: Independently polls and verifies block receipts on `https://testnet.hsk.xyz`.

## 2. API Endpoints & Request Headers (v2.3.0)

### 2.1. Endpoints
- **Base URL**: `https://api.merchant.hashkey.com` (configurable via `HSP_GATEWAY_URL`)
- **Order Creation Endpoint**: `POST /api/v1/merchant/orders`
- **Order Status Endpoint**: `GET /api/v1/merchant/orders/{order_id}`
- **Refund Endpoint**: `POST /api/v1/merchant/orders/{order_id}/refund`
- **Webhook Ingestion**: `POST /api/paypilot/webhooks/hsp`

### 2.2. Request Headers
Every request to the HSP API must be signed with HMAC-SHA256 according to official Merchant API v2.3.0 specifications:

| Header | Description | Example |
| :--- | :--- | :--- |
| `Content-Type` | MIME type | `application/json` |
| `X-App-Key` | Merchant API public key | `hsp_key_pub_847192034` |
| `X-Timestamp` | Unix timestamp in milliseconds | `1777209600000` |
| `X-Nonce` | Unique UUID or nanosecond nonce | `a1b2c3d4-e5f6-7890` |
| `X-Signature` | Hex-encoded HMAC-SHA256 signature | `4f8a9b2...` |

### 2.3. HMAC-SHA256 Message Construction
The signature string is generated by concatenating:
```python
# 1. Canonicalize body according to RFC 8785
body_str = canonical_json(body_dict) if body_dict else ""
body_hash = hashlib.sha256(body_str.encode("utf-8")).hexdigest()

# 2. Build HMAC message: METHOD\nPATH\nQUERY\nbodyHash\ntimestamp\nnonce
message = f"{method}\n{path}\n{query}\n{body_hash}\n{timestamp}\n{nonce}"

# 3. Compute HMAC-SHA256
signature = hmac.new(
    app_secret.encode("utf-8"),
    message.encode("utf-8"),
    hashlib.sha256
).hexdigest()
```

## 4. Webhook Notification & Signature Verification

When settlement occurs on HSK Chain, HSP delivers a webhook notification.

### 4.1. Header Format
```
X-Signature: t=1777209605,v1=9b8c7d6e5f4a3b2c1...
```

### 4.2. Verification Protocol (`app.paypilot.hsp_service.verify_webhook_signature`)
1. Parses `t` (timestamp) and `v1` (signature) from `X-Signature`.
2. Checks clock drift against tolerance (default: 300 seconds).
3. Constructs signed payload: `{t}.{raw_body}`.
4. Computes HMAC-SHA256 with `webhook_secret`.
5. Uses `hmac.compare_digest` to prevent timing attacks.

## 5. Dual-Mode Demo Adapter (`is_demo=True`)

When running in local test environments without live HashKey merchant credentials (`HSP_APP_KEY`, `HSP_APP_SECRET`):

- **Automatic Fallback**: The client utilizes `HspDemoAdapter`.
- **Transparent Attribution**:
  - `gateway_type`: `"HSP_GATEWAY_DEMO"`
  - `is_demo`: `True`
  - Order numbers are prefixed with `HSP-DEMO-`.
  - Transaction hashes are prefixed with `0xDEMO_` to prevent misrepresentation as live mainnet transactions.
- **Full Structural Fidelity**: Produces identical Cart Mandates, HMAC headers, and JSON responses so that 100% of downstream verification and evidence bundle logic runs unmodified.
